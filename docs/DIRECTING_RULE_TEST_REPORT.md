# 연출 규칙 이미지 테스트 보고서

검증일: 2026-08-11

## 목적

저장된 스토리보드 예시 이미지로 미장센·촬영·편집의 고정 규칙 12개가 필요한
상황에서만 발동하는지 확인했다. 규칙마다 발동 사례 1개와 비발동 사례 1개를 두어
총 24개 사례를 실제 비전 모델에 요청했다.

- 이미지: `public/img/viewer-test/`의 10개 패널
- 미장센 모델: `gpt-5.4-mini`
- 촬영 모델: `gpt-5.4`
- 편집 모델: `gpt-5.4`
- 실행기: `backend/app/tools/test_directing_rules.py`

촬영은 `gpt-5.4-mini`에서 축·화면 방향 판정이 같은 입력에도 흔들려 `gpt-5.4`로
올렸다. 같은 축 발동·비발동 통제쌍은 상위 모델에서 각각 3/3 통과했다.

## 판정 기준

비발동 사례는 진단이 없어야 한다. 발동 사례는 다음 조건을 모두 만족해야 한다.

1. 예상한 `rule_id`를 선택한다.
2. 예상한 진단 층위를 선택한다.
3. 화면 근거를 1~2개 제시한다.
4. 실행 가능한 수정 방향을 제시한다.
5. 해당 규칙에 연결된 이론을 정확히 1개만 사용한다.
6. 입력으로 답할 수 없는 결정에 한해서만 허용 범위 안에서 질문한다.

따라서 최종 통과 수치는 규칙 이름만 맞춘 결과가 아니라 구조와 내용 조건을 함께
검사한 결과다.

## 테스트 중 발견해 수정한 경계

- 미장센의 기능 요소와 시각적 위계를 분리했다. 대상이 식별되지 않으면 기능 요소,
  대상은 식별되지만 다른 요소보다 먼저 읽히지 않으면 시각적 위계다.
- 넓은 공간 속 작은 인물로 고립과 위험을 의도한 경우, 공간이 인물과 함께 시선을
  끄는 것을 위계 결함으로 만들지 않게 했다.
- 촬영의 주관 시점은 외부 투샷과 구분하고, 대치축은 동일 인물의 좌우 위치와 시선
  방향을 패널마다 직접 비교하게 했다.
- 카메라 화살표는 피사체의 화면 이동이 아니라 카메라가 이동·회전해 향하는 방향이다.
  시작 대상과 종료 대상이 있으면 그 벡터와 화살표를 직접 비교한다.
- 편집의 사건·정보 순서가 맞고 숏 크기·구도·정보량의 변화만 어긋난 경우에는 정보
  순서가 아니라 시각적 리듬으로 진단하게 했다.
- 감독이 이미 확정한 상태를 되묻는 질문은 막고, 실제로 비어 있는 배치 선택처럼 수정
  방향을 가르는 질문만 허용했다.

## 재현

`v3/backend`에서 환경 변수와 API 키가 준비된 상태로 실행한다.

```bash
../.venv/bin/python -m app.tools.test_directing_rules --concurrency 2
```

특정 규칙이나 반복 안정성은 다음처럼 확인한다.

```bash
../.venv/bin/python -m app.tools.test_directing_rules \
  --filter camera-axis-direction --repeat 3 --concurrency 1
```

각 `CASE_RESULT`의 `checks`가 모두 `true`여야 하며 마지막 `TEST_SUMMARY`가
`{"total": 24, "passed": 24, "failed": 0}`이어야 한다.

## 한계

- 저장 이미지와 의도·사건 설명을 조합한 통제 테스트이며 실제 사용자 연구를 대신하지
  않는다.
- 축 발동 사례는 동일 이미지를 좌우 반전한 통제 교란이다. 실제 콘티의 다양한 리버스
  숏과 축 이동은 별도 데이터가 필요하다.
- 정지 이미지에는 컷 길이와 정확한 타이밍이 없으므로 편집 리듬은 숏 크기·구도·정보량의
  시각적 변화만 판정한다.
- 카메라 움직임은 이미지에서 추측하지 않고 사용자가 남긴 화살표·시작 대상·종료 대상이
  있을 때만 판정한다.
- 생성형 모델 출력은 확률적이다. 핵심 경계는 3회 반복으로 확인했지만, 이미지 유형을
  늘린 장기 회귀 세트가 추가로 필요하다.
