# 현재 수정 작업 계획

작성: 2026-08-29

이 문서는 현재 확인된 baseline과 SceneLens 문제를 한 번에 섞어 고치지 않기
위한 작업 순서다. 항목마다 **문제 → 수정 기준 → 완료 검증**을 지키며,
완료된 뒤에만 다음 항목으로 이동한다.

## P0 — Baseline 생성 신뢰성

### B1. 대본에서 인물을 추출하고 모든 이미지 생성에 고정한다 — 구현 완료, 이미지 재현 검증 대기

**문제.** 대본과 무관한 예시 인물(하린)이 남았고, 패널 마지막 컷에는
레퍼런스에 없는 인물이 새로 나타났다. 현재 샷 설명에 인물 이름이 충분히
들어가지 않고, 이미지 생성이 캐릭터 레퍼런스를 모든 컷에 강하게 적용하는지
명확하지 않다.

**수정 기준.**

- 구조화 API가 대본의 실제 인물/역할과 외형 설명을 추출한다. 원문에 실명이
  없으면 해당 인물에게만 임시 고유 이름을 부여하고 역할은 설명에 보존한다.
  하드코딩된 인물은 없다.
- 캐릭터 생성 프롬프트에는 이름, 성별·나이·외형 등 추출된 사실을 모두 넣는다.
- 패널 프롬프트에는 해당 컷에 등장하는 인물 이름을 명시한다.
- 패널 생성에는 그 인물의 레퍼런스 이미지를 항상 첨부한다. 레퍼런스에 없는
  인물을 새로 추가하지 않도록 지시한다.
- 사용자는 샷 설명에서 `@이름`으로 등장 인물을 지정·수정할 수 있다. `@`가 없는
  경우에는 AI가 추출한 캐스트를 사용자가 확인할 수 있게 한다.

**검증.** 러닝 대본에서 캐릭터 카드와 8개 패널 모두 주인공·앞사람만 나오며,
마지막 컷에 제3의 인물이 생기지 않는다.

### B2. 인물·공간·방향 연속성 — 구현 진행 중

**문제.** Shot 3가 앞선 샷과 반대 방향으로 바뀌고, 재생성 때 인물·공간이
달라진다.

**수정 기준.**

- 각 컷은 앞 컷의 프롬프트와 생성 이미지를 연속성 입력으로 받는다.
- 동일 인물·장소 레퍼런스를 모든 관련 컷에 보낸다.
- 샷 설명에 없더라도 직전 컷의 이동 방향/화면 방향을 유지하라는 연속성 지시를
  생성 프롬프트에 넣는다. 의도적으로 바꿀 때만 샷 편집에서 변경한다.
- 재생성은 현재 컷만 바꾸되, 캐릭터·공간 기준은 유지한다.

**검증.** 동일 방향으로 달리는 Shot 1→3에서 180도 반전이 없고, 재생성 후에도
얼굴·의상·한강변 공간이 유지된다.

### B3. 생성 상태와 생성 게이트 — baseline 완료, SceneLens 대기

**문제.** 삽입/분할로 생긴 새 샷과 재생성에 진행 표시가 없어 실행 여부를
알 수 없다. 캐릭터 레퍼런스가 끝나기 전에 Panels 진입이 가능하다.

**수정 기준.**

- 캐릭터/패널/삽입/분할 생성 모두 대상 카드에 `생성 중` 상태를 보인다.
- 레퍼런스 생성이 하나라도 진행 중이거나 실패하면 Panels 시작 버튼은 비활성화한다.
- 실패한 카드에는 재시도 가능한 실패 상태를 보인다.

**검증.** 생성 요청 직후 대상 카드가 즉시 pending으로 바뀌며, 모든 필요한
레퍼런스가 완료되기 전에는 Panels로 갈 수 없다.

## P1 — Baseline 편집 흐름

### B4. 패널 편집 모달을 실제 수정 전에 읽을 수 있게 한다

**문제.** Edit 모달에 현재 이미지 미리보기와 현재 샷의 크기/앵글이 충분히
보이지 않는다. 적용 뒤 재생성의 결과와 진행 상태도 불명확하다.

**수정 기준.**

- Edit 모달 상단에 현재 패널을 큰 크기로 표시하고 확대할 수 있게 한다.
- 현재 shot size, angle, 등장 인물, 조립된 프롬프트를 기본값으로 표시한다.
- `완료`는 메타데이터/프롬프트 변경을 저장만 한다.
- `다시 생성`은 저장된 현재 값을 사용해 생성하고 카드에서 pending/완료/실패를 표시한다.

**검증.** 사용자가 현재 이미지와 현재 설정을 보고 수정한 뒤, 재생성 결과가
해당 수정만 반영하고 인물·공간은 유지된다.

### B5. 왼쪽 패널의 단계 이동을 되돌리기 동작으로 바꾼다

**문제.** Panels의 Story/Characters는 팝업이나 현재 맥락 확인이 아니라 초기
단계로 되돌아가며, Story로 갈 때 캐릭터 생성이 다시 시작된다.

**수정 기준.**

- Panels 안의 Story/Characters는 현재 데이터의 읽기/수정 뷰를 열며 생성 단계를
  다시 실행하지 않는다.
- 초기 단계로 되돌아가는 동작은 별도 명시 버튼으로만 제공하거나 제거한다.
- 이미 완료된 캐릭터 레퍼런스는 사용자 요청 없이는 재생성하지 않는다.

**검증.** Panels에서 Story/Characters를 열고 다시 돌아와도 이미지·진행 상태·
선택된 씬이 보존되고 API 생성 호출이 없다.

## P2 — SceneLens 입력·컷 플랜

### S1. 대본 구조화는 내용을 누락하지 않고 시놉시스를 구체화한다

**문제.** 구조화가 중요한 정보(예: 영수증의 `절대 7시 15분 버스를 타지 말 것`)
를 생략한다. 한 줄당 한 패널이라는 압박이 시놉시스를 빈약한 문장 목록으로 만든다.

**수정 기준.**

- 구조화의 첫 원칙은 원문 사건·소품·문구·결말 단서를 보존하는 것이다.
- 사용자가 쓴 짧은 시놉시스를 씬별 행동·반응·인과관계로 구체화한다.
- 한 원문 문장이 여러 줄/여러 패널로 전개될 수 있으며, 반대로 여러 줄이 하나의
  패널의 맥락으로 남을 수도 있다. 줄 수가 곧 패널 수가 되지 않는다.
- 새 플롯/새 인물/새 결말은 만들지 않지만, 기존 사건을 읽히게 하는 연결 행동과
  반응은 `filled=true`로 명시한다.

**검증.** 영수증 문구, 버스 탑승, 경고를 무시한 선택이 모두 구조화 결과에 남고,
사용자는 AI가 보강한 부분을 구분해 확인할 수 있다.

### S2. Cut plan의 Moment 편집을 단순화한다

**문제.** Moment/Beat의 위·아래 이동이 복사처럼 보이거나 상태를 망가뜨린다.
컷 플랜에서 split/merge 같은 해결책을 제시하는 것도 과하다.

**수정 기준.**

- Moment라는 사용자 노출 용어와 위/아래 이동 기능을 제거한다.
- 컷 플랜은 컷 내용 확인·수정과 삭제(X)만 남긴다.
- 편집 에이전트는 split/merge/insert 해결책을 제시하지 않고, 발견한 문제와
  화면 근거만 말한다.

**검증.** 컷 플랜에서 순서 변경/복사로 오해할 조작이 없고, 편집 점검은 문제
설명만 제공한다.

### S3. Panels setup에서 AI가 채운 기준을 먼저 제시한다

**문제.** 성별·나이·외형 기준 일부가 비어 있어 사용자가 처음부터 채워야 한다.

**수정 기준.**

- 대본에서 추출 가능한 인물 정보는 모두 텍스트 기준으로 먼저 채운다.
- 사용자는 그 값을 고치거나 비울 수 있지만, 빈 상태를 기본값으로 두지 않는다.
- 필요한 레퍼런스가 완료되기 전에는 Panels 시작을 막는다.

**검증.** 캐릭터 설정 화면에서 AI가 추출한 이름·성별·나이·외형 설명이 먼저
보이고, 사용자는 검토 후 생성한다.

## P3 — SceneLens 검토·적용 상태

### S4. 적용된 제안/수정은 즉시 해결 상태가 된다

**문제.** 대본 점검 제안을 적용해도 카드가 남고, 수정 적용 뒤에도 해당 문제의
상태가 바뀌지 않는다. Panels에서 별도 Accept를 해야만 타임라인에 반영된다.

**수정 기준.**

- 제안을 적용하면 원문/대상 변경과 동시에 해당 카드를 `적용됨`으로 전환하거나 숨긴다.
- 편집 수정은 검토 화면에서 즉시 Accept/Reject하고, Accept면 즉시 보드·타임라인을 갱신한다.
- 분할처럼 여러 컷이 생기는 변경은 기존 컷을 대체하고 모든 새 컷을 pending으로 표시한다.

**검증.** 같은 제안을 두 번 적용할 수 없으며, Accept 직후 상단 타임라인과 패널이
현재 보드 상태를 반영한다.

### S5. 관계 방향과 모든 관련 렌즈를 정확히 표시한다

**문제.** `consequence` 설명의 원인/영향 렌즈가 뒤바뀌고, 관계 보기에
미장센·편집만 표시되어 촬영 등 다른 관련 렌즈가 빠진다.

**수정 기준.**

- 관계 데이터의 source(원인) → target(영향) 방향을 UI 문장과 그래프에 동일하게 쓴다.
- 하나의 이슈가 연관된 모든 렌즈를 표시한다. 관계가 여러 개면 모두 별도 항목으로 보인다.
- `처음 발견한 렌즈`와 `영향받는 렌즈`를 섞지 않는다.

**검증.** 미장센에서 처음 발견된 문제의 consequence는 `미장센 → 편집/촬영`으로
표시되며, 관련된 세 렌즈가 모두 보인다.

### S6. 관객 읽힘의 답변을 연출 검토 트랙에 보존한다

**문제.** 관객 읽힘에서 답변을 남긴 뒤 연출 검토로 가면 관객 트랙/행이 사라진다.

**수정 기준.**

- 관객 답변을 이벤트로 저장한다.
- 연출 검토 화면에 관객 행을 추가하고, 답변이 연결된 문제/컷 위치에 유지한다.

**검증.** 관객 답변 후 연출 검토 화면으로 이동해도 관객 행, 대상 위치, 답변 요약이
그대로 보인다.

## 작업 순서

1. **B1** 인물 추출·참조 강제
2. **B2** 인물·공간·방향 연속성
3. **B3** 생성 상태·Panels 진입 게이트
4. **B4–B5** baseline 편집/이동 흐름
5. **S1–S3** 구조화·컷 플랜·setup
6. **S4–S6** 검토·관계·관객 읽힘

각 항목은 실제 브라우저에서 해당 재현 사례로 확인하고, 생성 결과/상태 변화가
확인된 뒤 다음 항목으로 넘어간다.
